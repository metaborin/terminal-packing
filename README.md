# 端末回収ノート

iPhone 1台で、端末番号の照合と箱ごとの梱包記録を行うWebアプリです。

**[アプリを開く](https://metaborin.github.io/terminal-packing/)**

## 使い始める

1. iPhoneのSafariでアプリを開き、「共有」→「ホーム画面に追加」を選びます。「Webアプリとして開く」が表示されたらオンにします。
2. ホーム画面のアイコンから開き、「準備・保存」で回収する端末番号の一覧を登録します。
3. 箱を選んで「カメラで自動読み取り」を押し、カメラの利用を許可します。シールを枠に合わせて止めると、異なる映像で同じ番号が2回続けて読めると、その画像を取り込んで別の処理方法で再確認し、照合結果を表示します。撮影ボタンを押す必要はありません。写真からの読み取り・端末番号の手入力も使えます。
4. 実物の番号を確認して箱に入れた後、「梱包完了」を押します。保存が完了すると次の端末を読み取るカメラが自動で開きます。9台目では次の箱番号へ進み、カメラ画面にも新しい箱番号を表示します。
5. 箱ごと・作業終了時にバックアップをファイルに保存します。

番号一覧は8桁の端末番号を1行1台で貼り付けるか、CSV・TSV・テキストファイルから読み込めます。複数列のCSVでは「端末番号」または「管理番号」列を使います。今回の回収対象であることを確認して取り込んでください。

## 機能

- 映像を1倍・1.5倍・2倍に拡大（初期値2倍）。近づけすぎずにシールを合わせるための表示
- カメラの異なる映像で2回一致した後、取り込んだ2枚目を濃淡調整して再確認
- 通常の成功時の文字認識処理を6回から3回に削減。読み取り間隔の待ち時間も350msから60msへ短縮
- 再確認中は取り込んだ画像を表示し、iPhoneを止め続ける必要をなくす
- 不一致・複数候補・低い読み取り評価では照合結果を確定せず、読み直しを案内
- 梱包記録の保存後、次の端末のカメラを自動で開く。直前に記録した番号が映っていても、次の端末を待つ
- 全台の梱包完了・現在の箱が満杯の場合は自動再開せず案内。カメラ右上の×で中断可能
- 写真の文字認識と番号一覧との照合
- 箱番号・日時を伴う梱包記録、二重登録防止、取消履歴
- 箱番号001～129をボタン・一覧で選択。9台の記録で次の箱へ自動切り替え
- 以前の箱01などの表記は001へ統一。端末番号・梱包日時・取消履歴・独自の箱名を保持
- 未梱包一覧・箱別台数・番号検索
- CSV書き出し、JSONバックアップ保存と復元
- ホーム画面から独立したアプリ画面で起動（PWA）
- 初回に画面を保存し、手入力の照合・記録はオフラインで利用可能
- 写真読み取り用データを約14MB保存すると、OCRもオフラインで利用可能
- 作業の区切りで適用できる更新案内。梱包記録は更新後も引き継ぎ

自動読み取りは最初に2倍で開きます。シール1枚の8桁全体を枠に合わせ、近づけすぎず、反射を避けてスマホを止めます。ぼやけたりカメラが切り替わったりするときは、ピントが合う位置まで少し離してください。1倍・1.5倍・2倍を選べ、選んだ倍率はこのブラウザに保存します。倍率を変えると確認回数を0に戻し、変更前の読み取り結果は使いません。

拡大はアプリ内の映像表示と読み取り範囲の調整です。倍率ボタンではカメラのレンズを切り替えませんが、iPhone自身の自動マクロ切り替えを禁止する機能ではありません。拡大で画像の細部が増えるわけではないため、読みにくい場合はピントや明るさを調整してください。

「一致 1 / 2 回」のように確認状況を表示します。2回一致すると映像を固定し、「ここからはiPhoneを動かしても大丈夫です」と表示して、その画像を再確認します。再確認が失敗したら固定画像を消し、枠に合わせ直すよう案内します。読み取りが食い違ったら数え直します。番号一覧に似た番号があっても置き換えません。繰り返し確認しても同じ誤読が続くことはあるため、正しさの保証や正解確率の表示ではありません。最後に実物の8桁を確認し、箱に入れて「梱包完了」を押してください。読み取りだけで梱包記録は増えません。

カメラを閉じる、アプリから離れる、カメラが停止する場合は、自動読み取りを停止し、遅れて返った結果を無視します。次の端末を読むときは、カメラをもう一度開いてください。自動読み取りが難しい場合は、カメラ画面の「iPhoneの撮影画面を使う」や「写真から読み取る」を利用できます。写真選択では、シール中央をタップして、回転・拡大縮小で枠に合わせます。写真方式の結果も実物と見比べてください。

箱番号は「001」「002」の3桁です。9台目の「梱包完了」を押すと、その端末を元の箱に保存してから、次の番号へ自動で切り替えます。たとえば001の9台目は001に記録し、続く端末は002に入れます。切り替え後の番号は画面に表示します。1箱への10台目の追加はできません。

「前の箱」「次の箱へ」や一覧からの切り替えも使えます。照合結果を確認している間は箱番号を固定します。記録を取り消しても現在の箱番号は戻らないため、元の箱に補充する場合はその箱を選び直してください。次の番号の箱が既に満杯でも自動では飛ばさず、空きのある箱を選ぶよう案内します。129の次の番号は作りません。以前の独自の箱名は残り、9台になったら一覧で次の箱を選びます。

既存記録や旧バックアップの「箱01」「01」「1」などは同じ箱番号「001」にそろえます。名簿・端末番号・梱包日時は引き継ぎます。箱に貼る振り分け表も「001」のように記入してください。

## データの保存

写真は文字認識にだけ使用し、アプリから送信・保存しません。番号一覧と梱包記録は、この端末のブラウザ内（IndexedDB）に保存されます。GitHubや他の利用者とは共有されません。CSV・バックアップ・実物写真はこのリポジトリに含まれていません。

ブラウザの閲覧データの消去や端末故障で記録を失う可能性があります。JSONバックアップを別途保存してください。CSVは確認用一覧、JSONは復元用です。Safariとホーム画面アプリで保存領域が分かれる場合があるため、作業は同じアイコンから続けてください。

別のURLの版から移る場合は、旧版でJSONバックアップを保存し、この版の「準備・保存」から復元します。記録は自動では移りません。

## 動作確認

元のアプリはChromium・WebKitで照合、梱包、取消、保存、復元等の操作を確認しています。PWA版では両エンジンで通信を遮断した新規画面の起動・OCR・梱包・記録保持、更新時の記録維持も確認しています。iPhone実機の撮影・共有メニュー・ホーム画面起動は未確認です。最初は通信できる場所で数台を試してください。

「準備・保存」では、アプリとして起動しているか、画面・写真読み取りのオフライン準備ができているかを確認できます。読み取りデータがブラウザから消去された場合は再準備を案内します。端末自体の故障などに備え、作業終了時のバックアップも続けてください。

更新が見つかると画面上に案内します。照合結果の確認・撮影・記録保存の途中では更新を適用できません。以前の版が表示される場合は、通信できる場所で開き直し、更新案内に従ってください。閲覧データの消去は必要ありません。

## 構成と公開

ビルド不要のHTML・CSS・JavaScriptです。公開ファイルは `docs/` にあります。GitHub Pagesの公開元は `main` ブランチの `/docs` です。

OCRはTesseract.jsをブラウザ内で実行します。必要なライブラリと認識モデルは `docs/vendor/` に同梱しています。利用条件は `docs/licenses.html` とvendor内のライセンスを参照してください。

更新時は `docs/sw.js` の `APP_VERSION` とHTML内の版番号付きリソースURLを更新します。新しい画面のキャッシュが揃ってから更新を案内し、利用者の操作で切り替えます。データベースの名称は変更しないでください。
